# 0.9.3 验证记录

日期：2026-10-25。三端统一 0.9.3，Android versionCode 21。

## 验证结果

- Node：工作源码与脱敏公开源码均 146 项通过。
- Android JVM：17 项通过。
- 原生 Android：本次变更相关的 26 个不同用例全部通过，含连接恢复 11 项、聊天布局 7 项、多电脑通知 5 项、电脑管理 3 项。先跑完整集合，修正布局测量和测试夹具并重跑 7 项界面测试；没有将重复执行计为新用例。
- lintDebug：0 错误、27 条现有警告。
- 模拟器：1080×2400、密度 480（360dp）。键盘弹出且存在离线状态和待确认操作时，验证输入区至少 48dp、文字行至少 22dp，输入区完整位于键盘上方；草稿可编辑，发送正确禁用。

## 已复现并修复的问题

相同电脑身份的两个连接实例会互相接管。修复前，缩短重试间隔的 Node 测试中，预期只建立 2 次连接，实际建立 11 次；Android 测试也出现接管后再次自动连接。修复后，接管通知使旧实例停止重试，新实例保持连接。

另外使用实际中继代码建立独立 TLS 服务，让两个连接器运行实例依次接管，验证电脑端手动「连接 Codex」可以恢复原实例、保留原身份，另一个实例正常让出连接。此测试不访问真实聊天。

覆盖普通断网恢复、静默连接失效、握手超时、HTTP 403、WebSocket 4003、授权恢复后的手动连接、确认响应丢失后查询回执、后台恢复、不同电脑间草稿与待确认状态隔离。待确认操作不自动重发。

界面回归还覆盖项目搜索、新建对话、模型权限、完整工具记录、真实隧道网页预览、文件读取与预览、待确认详情、清除前取消以及多行输入。夹具将加密与发送排队作为一个串行操作，避免测试工作线程把加密序号乱序发送。

## 公网检查的范围

本次只读检查时，中继容器没有重启或 OOM 记录，CPU 和内存负载正常，最近两小时日志没有错误输出。没有更改线上服务配置。这只能说明检查时刻未发现上述服务器异常，不能证明历史网络没有波动。

用户尚未确认手机与 Windows 连接器的版本，也未提供该 Windows 设备的现场日志，不能认定所有旧截图都由连接抢占导致。建议两端同时更新，再观察是否还有异常。
