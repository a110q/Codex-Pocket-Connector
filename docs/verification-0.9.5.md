# 0.9.5 验证记录

日期：2026-10-26。三端版本 0.9.5，Android versionCode 23。

## 复现与原因

本地项目端口正常，直接请求首页返回 HTTP 200。原生 Android 模拟器通过生产代码的隔离中继、连接器和 TCP 代理可以加载项目；使用缓存时，经公网中继也能加载。

清空 WebView 缓存后，真实 Vite 项目经公网中继首次加载失败：页面脚本尚未下载完成，0.9.4 的固定 30 秒计时就中断加载，60 秒验收结束时仍未渲染登录页。这个路径不在之前的小型静态页面验证范围内。

加入转发压缩后，同样清空缓存、经过同一个公网中继，页面约 10 秒显示登录内容；后续回归等待内容稳定后截图，确认登录表单实际呈现。这个时间仅代表本次网络和项目条件，不是所有页面的速度承诺。

测试使用独立的测试电脑身份，不接管真实用户手机、不修改真实账号、聊天或项目。只打开项目登录页，没有提交登录或业务操作。真实项目截图保存在本地私有验证目录，未放进公开源码。

## 自动化覆盖

- Node：148 项通过。新增测试验证压缩前后大型脚本逐字节一致、实际流量减少，以及旧手机继续收到原始数据。
- Android JVM：17 项通过。
- Android 原生：12 项相关用例通过，包括真实中继冷加载、45 秒停滞后显示重试、重试重建连接、压缩边界与旧格式兼容、聊天链接和小窗等回归。
- 另以同一原生加载用例验证持续 35 秒下载的脚本，页面最终渲染成功；不会再在第 30 秒被停止。
- APK 使用原签名构建；Mac 签名及 Windows 打包完整性检查随发布执行。

## 兼容与范围

压缩由手机在 `preview.read` 中显式请求，电脑仅在压缩确实减少大小时返回 gzip；旧手机保持原始传输，新手机兼容旧电脑。压缩发生在端到端加密通道内部，不需要修改中继，不改写 HTTP 内容，也不跳过 HTTPS 校验。

手机与电脑都更新才能启用压缩。Windows 仍未做真实 Windows 11 电脑连接验收；该平台完成了构建和包内容校验。手机品牌及 WebView 版本差异、其他页面脚本问题仍可能需要进一步排查。
