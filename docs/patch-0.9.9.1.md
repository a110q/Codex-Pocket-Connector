# 0.9.9.1：首次连接恢复和列表运行状态

版本号 0.9.9.1，Android versionCode / pocketBuild 33。保留 0.9.9 的界面和桌面排队消息同步。

## 列表不显示运行中

在实际 Mac 上对照两个只读接口，桌面返回的 3 条 `active` 会话，在连接器的独立 App Server 列表中全部为 `notLoaded`。独立进程未加载桌面拥有的会话，因此其列表不能代表桌面的运行状态。旧版本只有在手机打开对话、订阅实时记录后才补齐状态。

修复后，对话列表同时读取桌面的摘要状态，每 5 秒的现有列表刷新直接更新运行标记。Pocket 自己拥有的会话从所属进程读取 `includeTurns: false` 的状态元数据。查询不会逐个打开对话、下载历史或获取运行会话的写入权；完成和等待状态同样参与刷新。桌面摘要接口当前最多返回最近 50 条非置顶会话及全部置顶会话，其余会话仍使用已有明确状态或未知状态。

实际 Mac 复核：修复前 3 条 `active → notLoaded`，修复后 3 条 `active → active`，实时历史订阅数量为 0。

## 首次确认超时

旧手机仅在收到中继的在线状态通知时发一次确认，丢失通知或首次确认回复后，需要等满 20 秒，再重新建立连接。新版本在 WebSocket 建立后主动确认，并在同一条连接内每 3 秒重试；仍保留 20 秒的总期限，避免无限等待。心跳回复丢失时，也在原来的期限内重试只读探测。

首次确认超时和已连接后的心跳超时使用不同提示。手机、电脑时间相差超过两分钟时，电脑明确回复校时提示，不再静默丢弃确认。加密、防重放、操作过期检查及操作回执机制保持有效；不会因恢复连接自动重发消息。

截图那次超时发生在分阶段日志启用之前，无法从后来成功的连接证明原来具体在哪一跳中断。后续采集到两次成功确认，电脑收到确认后立即回复，手机与电脑时间差约 1 秒，没有记录到解密错误。这次修复覆盖了可复现的首次通知/确认丢失恢复缺口，不将原截图的未知网络原因写成已证实结论。

## 诊断日志

手机“更多 → 连接诊断”及错误条的“详情”可查看、复制最近连接阶段，恢复后仍可查看。电脑在私有状态目录记录 `connection-diagnostics.jsonl`；手机记录在应用私有目录。日志包括连接阶段、时间、重试次数、错误类型和就绪标记，不记录配对密钥、授权令牌、消息正文或聊天记录。日志有大小上限并轮转。

更新手机 APK 和电脑连接器后，首次确认重试与新诊断同时生效；列表运行状态的关键修复位于电脑连接器，不需要升级公网中继。
