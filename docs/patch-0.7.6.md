# 电脑连接器 0.7.6：恢复桌面连接与消息占用冲突

桌面 IPC 断开后，旧版仅在启动或新建时恢复连接。手机向电脑持有的已有会话发送消息，会跳过桌面持有者发现，尝试启动第二个写入者，收到 `already has an active writer`。随后该提交前失败又被记为结果不确定，手机留下黄色等待确认提示。

现在读取、发送和设置会重新连接桌面 IPC，先发现并跟随电脑已经打开的会话。若发现完成后电脑才打开会话，且恢复接口明确拒绝获取写入权，会再发现一次持有者，然后沿用桌面会话发送。该重试发生在消息提交之前；消息提交后超时仍保留不确定状态，不自动重发。发送前必须取得实时桌面快照，不能用旧历史猜测当前轮次。

明确未提交的发送失败会解除待确认并让安卓恢复草稿。旧版记下的精确 `thread <ID> already has an active writer` 发送失败，在手机点击「重新确认」时改为已拒绝，不重新执行原请求；草稿回填后可再次发送。其他历史超时继续要求用户核对，避免重复消息。

更新方式：完全退出旧 Pocket 连接器，打开 0.7.6。安卓继续使用 0.7.2，中继、账户和扫码配对保持原配置。

验证：98 项 Node 测试通过，覆盖断线后恢复、发现与接管之间的竞争、占用拒绝、快照缺失、原请求去重以及旧待确认记录恢复。由 LaunchServices 独立启动应用，在专用验收会话中主动断开桌面 IPC，再发送普通消息及带模型/推理设置的消息；两次均跟随桌面持有者，没有启动第二个写入进程，每次消息只提交一次，回复可从桌面实时读取。Windows 仅完成构建和包完整性检查，尚待 Windows 11 实机验收。
