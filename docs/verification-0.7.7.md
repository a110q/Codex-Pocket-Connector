## 自建中继实际链路

使用独立 Docker Compose 中继、独立 TLS 证书、测试账号及测试电脑身份，未更改默认生产中继。按自建说明从部署走到聊天：

1. 构建容器并挂载证书、数据库目录，验证 `/healthz`。
2. 在电脑连接器填写 HTTPS 地址、导入公开证书并验证；错误的 HTTP 地址、私钥或证书不能切换服务。
3. 手机注册该服务账号，界面显示等待审批；管理员批准后继续。
4. 手机提交配对后显示「配对中，等待电脑确认」，电脑确认后自动加载工作空间。
5. 向用户明确授权的「Codex Pocket 验收测试」会话发送蓝色图片及文字；真实 Codex 回复识别出蓝色，历史附件可再次读取。
6. 模拟桌面已经发送成功但回执丢失，按稳定请求 ID 找回结果。只提交一次，正式时间线只有一条对应用户消息。
7. 重启 Docker 中继，保留数据库、账号和配对；手机重新握手后恢复连接和历史，没有重发消息。

部署时发现并修复 Compose 示例的 `tmpfs` 引号问题。账号、配对、会话缓存及草稿按服务隔离；服务切换测试确认原服务 Token 不会传给另一服务。

该链路证明当前独立部署配置可工作；域名解析、公网证书、云安全组和具体网络仍由部署者验证。

## 电脑安装包

- **macOS**：正式 `.app` 的通用二进制及签名检查通过；独立启动原生窗口，确认第二步未完成时第三步不可进入。原生文件选择器可导入公开证书，连接自建中继后显示配对二维码；关闭窗口后本次实例监听端口释放。
- **Windows**：EXE / ZIP 交叉编译、压缩包完整性及所含模块检查通过。当前没有 Windows 11 实机，尚未验收该系统上的实际 Codex 安装识别、WebView2 窗口及进程退出。不能将打包成功视为实机通过。
- **Android**：Release 使用原签名、R8 混淆及资源压缩，更新保留配对与账号；版本号 0.7.7 / versionCode 13。公开安装包保留既有默认公网服务配置。

源码与 Release 发布前扫描凭据及私人路径；公开源码使用示例配置，安装包保留公开连接地址与证书，不包含部署用 SSH 密码、管理员密码、签名私钥或用户配对数据。
