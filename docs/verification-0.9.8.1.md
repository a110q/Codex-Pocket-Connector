# 0.9.8.1 验证记录

验证日期：2026-10-29。本记录对应 0.9.8.1 发布版本。公开源码使用占位配置，安装包保留预设公网服务。

## 连接问题的证据

新增的三个回归用例在修复前全部失败，分别复现独立连接器不发送就绪事件、Codex 初始化阻塞电脑服务启动，以及在同一条手机连接上无法自动恢复。修改后全部通过。

- 手机握手即时返回真实就绪状态，不阻塞初始化；初始化完成后主动通知。
- 初始化超时后能发起下一次连接，旧初始化结果不能覆盖新状态。
- 加密心跳无需 Codex 初始化完成即可回复；非就绪时拒绝操作，恢复后可继续。
- 电脑恢复沿用手机原中继 socket，不依赖手动重连。
- 旧连接器尚未就绪时，手机会重新握手确认。
- 中继 WebSocket 仍然健康但电脑不回复加密探测时，手机到期结束失效连接，待确认消息仅回调一次。
- 发送结果不明时保留原操作 ID 和草稿，通过回执查询确认，不自动重发。

## 测试结果

- Node：170 项全部通过，包含端点权限、命令去重、回执恢复、桌面 IPC、传输断线及三段/四段版本排序与 Windows 资源版本验证。
- Android JVM：21 项全部通过，新增连续执行记录分组、消息顺序、轮次边界与流式新增稳定性的 4 项回归；Lint 通过，无 error。
- Android 模拟器：最终连接关闭竞态保护加入后，连接恢复、任务状态、多电脑通知、图片/附件、审批、电脑切换和中继切换的 43 项整合回归全部通过。
- 执行过程折叠完成后，界面与布局、图片/文件、审批的 25 项模拟器回归全部通过。验证默认折叠、展开/收起、原始完整详情读取、实时记录和状态更新、不同轮次与对话隔离，以及 80 条执行记录按需渲染后仍能折叠。正文、附件、模型与权限设置、审批和网页小窗均可继续使用。
- 这轮回归曾稳定复现离线时无效网页地址的错误提示被“连接详情”隐藏；修复为地址栏下方直接提示并保留焦点，原失败用例在最终整轮回归中通过。
- 早期扩展测试缺少 `servicePairing` 测试参数，导致两项中继切换用例在进入产品流程前空指针失败。补齐虚构隔离参数后，完整 15 项全部通过；不使用真实账号或生产配对资料。

## Mac 安装包实测

直接运行 `releases/mac/Codex-Pocket-Connector-0.9.8.1.app` 的原生可执行文件，使用项目内独立状态目录。确认版本、连接 Codex、显示二维码、局域网手机配对、加密握手、加密心跳和只读加载对话成功。通过应用正常退出，电脑管理端口和局域网端口均可重新绑定。未发送消息、修改用户聊天或写入项目文件。

另行对实际安装的 Codex 目录进程做三次断开恢复：四次初始化均就绪，IPC 可用，对话目录可读取；就绪/断开事件序列正确。整个探测不提交消息。

公网中继的四次 HTTPS 健康检查全部 HTTP 200，耗时 45–141 ms。这说明检查当时健康接口可用，不能证明网络在其他时段或负载下绝不发生问题。
